# Orchestra 0.5.3

**Released:** 2026-04-14

## Fixed

- **Stop hook path hardcoded to installer's machine.** `setup link` wrote hook commands like `bash /Users/paulonasc/Documents/orchestra/hooks/orchestra-stop.sh` into `.claude/settings.json`. Anyone who cloned the repo or moved their Orchestra installation got `No such file or directory` on every session stop. Fixed by installing thin wrapper scripts at `~/.orchestra-state/hooks/` and using `bash $HOME/.orchestra-state/hooks/<hook>.sh` in settings.json — `$HOME` expands at runtime, so each user's shell resolves their own path.
- **Hook paths stale after move or update.** Wrappers are regenerated every time `setup sync` runs, so moving Orchestra or adding/removing hooks is fixed with one command.
- **Stale settings.json entries for removed hooks.** `setup sync` now removes wrapper files whose source hook no longer exists, and the install_hooks loop rebuilds settings.json from scratch each run.
- **settings.json leaking machine-specific paths into git.** Added `.claude/settings.json` to `.gitignore` in `setup link` so accidentally-committed machine paths can no longer affect other users.

## Added

- `install_hook_wrappers()` in `setup` — creates/regenerates/cleans up `~/.orchestra-state/hooks/` wrappers on every `link` and `sync`.
- `~/.orchestra-state/.install-dir` — records the current Orchestra installation path for diagnostics.
- 7 new tests in `setup-hook-paths.test.ts`: wrappers created on link, path regeneration on sync, hook add/remove sync, `$HOME` expansion smoke test, missing wrapper error, `.gitignore` entry.

## Actions

Re-link your repos to get dynamic paths:
```bash
./setup sync
```

This rewrites settings.json to use wrapper paths and creates the wrappers in `~/.orchestra-state/hooks/`. No further action needed.
