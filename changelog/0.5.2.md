# Orchestra 0.5.2

**Released:** 2026-04-14

## Fixed

- **Stop hook never fired (root cause of 12-day data gap).** The recursion guard in `hooks/orchestra-stop.sh` used `grep -q '"stop_hook_active"'`, which matched the JSON key regardless of its value. Claude Code always includes `"stop_hook_active"` in the Stop hook payload — even when `false` — so every invocation exited early before writing any telemetry or triggering sync. Fixed to check `'"stop_hook_active": *true'`.
- **`hook_stop` event missing `session_id` and `duration_s`.** Both fields were absent from every `hook_stop` event, leaving them null in the DB. The stop hook now reads a start-time file written at session start and emits both fields. `duration_s` is `null` when no start file exists (e.g. first session after install).
- **Events from crashed/abandoned sessions never synced.** Sync was only triggered from the stop hook. If a session was force-quit or crashed, its events piled up in the local queue indefinitely. `orchestra-session-start.sh` now triggers a background sync at the top of every session to flush the previous session's queue.
- **`session_start` and `nudge_fired` silently dropped by live edge function.** The deployed Supabase function was stale — it predated the `VALID_EVENTS` additions for these two types. Both were silently dropped with `inserted: 0`. Deployed updated function.

## Added

- Start-time file written by session-start hook (`session-start-<session_id>` in `.orchestra/.logs/`), enabling duration tracking across session lifecycle.
- 21 new tests: `stop-hook.test.ts` (12 tests) and `session-start-sync.test.ts` (9 tests including a full start→stop duration roundtrip integration test).
- 5 new e2e tests in `telemetry-pipeline.test.ts` covering new event fields, mixed batches, and the rate limiter — all assertions strict against the live endpoint.
